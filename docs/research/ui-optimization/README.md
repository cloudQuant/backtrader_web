# UI-210 真实任务研究工具包

本工具包用于验证 [UI_OPTIMIZATION_TODO.md](UI_OPTIMIZATION_TODO.md) 中已交付的 UI-201 至 UI-207。
它不是产品可用性的替代证明：只有独立参与者完成受控任务后，UI-210 才能关闭。

## 准备

1. 招募三类互不重复的参与者各 3 人：独立交易者、量化研究员、风控/管理角色。
2. 使用本地 mock 环境或明确无真实下单权限的测试环境；不要使用个人账户、真实持仓、令牌或私有策略源码。
3. 测试主持人只读任务原文，不提示按钮位置、路由或下一步操作；只有参与者卡住超过 90 秒时才记录干预。
4. 每场 20 至 30 分钟：2 分钟说明、5 分钟无引导任务、5 分钟追问、其余时间记录与收尾。

## 任务脚本

### 独立交易者

在手机宽度下打开行情页：确认当前刷新状态，暂停自动刷新，打开一个品种的图表，再返回行情列表。

成功：5 分钟内完成，能解释刷新是否暂停，且没有误删自选或误认为已执行真实交易。

### 量化研究员

从策略库选择模板，建立研究工作区，发起回测，并在结果页说明当前状态和下一步应做什么。

成功：5 分钟内完成；无需主持人指出入口；能区分“进行中/失败/完成”状态并说出下一步。

### 风控/管理角色

查看网关状态，筛选数据脚本，并说明一次运行或启停操作的风险边界。

成功：能区分查看、普通操作和危险操作；未在未确认的状态触发危险动作。

## 记录与判定

每一场会话在 [sessions.csv](sessions.csv) 中增加一行，并把可复现问题写入
[decision-log.md](decision-log.md)。不记录姓名、邮箱、账户标识、策略代码、屏幕录制链接或任何生产凭证。

任务完成率按角色分别计算：`完成数 / 已完成会话数`。以下任一条件使问题进入开发 backlog：

- 同一问题在同一角色至少 2 人中出现；
- 造成任务失败、误操作、错误理解风险或无障碍阻断；
- 有可复现的证据且严重度为高。

只出现一次的视觉偏好记录为观察项，不自动转为实现工作。

## UI-210 关闭条件

- 每个角色至少 3 名独立参与者完成对应任务；
- `sessions.csv` 中包含完成状态、耗时、错误和干预情况；
- 每个达标问题都有 `decision-log.md` 记录，且已回写到 [UI_OPTIMIZATION_TODO.md](UI_OPTIMIZATION_TODO.md) 的对应 UI-ID；
- 修复项完成后，补充代码/浏览器验收证据。
