# 迭代129 - 增加知识库和 AI 问答 - 实施计划

> **文档状态**: 已优化，作为开发执行基线
> **最后更新**: 2026-04-23
> **建议周期**: 2 周（10 个工作日）

---

## 1. 实施目标

在 2 周内交付“知识库管理 + 文档管理 + 索引 + AI 问答”的 P0 闭环，并为 AI 助手、模型管理等 P1 能力预留结构。

交付优先顺序：

1. 菜单与路由接入
2. 数据模型与 API 骨架
3. 知识库 / 文档主流程
4. 索引与问答主流程
5. 测试与验收

---

## 2. 开发前置条件

### 2.1 必须先确认

1. ReqDocs 源实现补核对（至少确认核心数据模型、RAG 流程、导入格式支持）；
2. SurrealDB 本地开发环境可启动并能被后端访问；
3. SiliconFlow API Key 与默认模型方案可用；
4. PDF / DOCX 是否纳入本期强交付。

### 2.2 工程准备事项

| 事项 | 优先级 | 说明 |
|------|--------|------|
| 后端依赖补充 | P0 | surrealdb、tiktoken |
| P1 依赖预埋 | P1 | python-docx、PyMuPDF、markdownify |
| 环境变量补充 | P0 | SurrealDB / SiliconFlow |
| Alembic 迁移脚本 | P0 | 新增 ORM 后同步数据库演进 |
| 路由优雅注册 | P0 | 新模块走 `_register_optional_router()` |

---

## 3. 阶段划分

## 阶段一：基线搭建（第 1~2 天）

**目标：** 让新增功能能“挂得上去、启得起来、跑得通骨架”。

| 任务 | 说明 | 交付物 |
|------|------|--------|
| 核对源实现与文档 | 核对 ReqDocs 关键能力清单 | 核对结论记录 |
| 补充后端依赖与环境变量 | 完成基础配置 | `.env.example` 更新、依赖清单 |
| 新增 ORM / Schema 骨架 | 建立知识库相关模型与 schema | model/schema 文件 |
| 编写 Alembic 迁移 | 建表与索引 | migration 文件 |
| 新增 API router 骨架 | knowledge_base / kb_chat / rag | router 文件 |
| 新增前端页面骨架 | `AIChatPage.vue` / `KnowledgeBasePage.vue` | 页面骨架 |
| 更新菜单与路由 | 修改 `AppLayout.vue` + `router/index.ts` | 可访问新入口 |

**阶段退出标准：**

1. 菜单位置正确；
2. 新页面可访问；
3. 后端新路由已注册；
4. 数据库结构可初始化。

---

## 阶段二：知识库与文档主流程（第 3~5 天）

**目标：** 完成知识库与文档管理闭环。

| 任务 | 说明 | 交付物 |
|------|------|--------|
| 知识库 CRUD | 列表、详情、创建、编辑、删除 | 后端 API + 前端页 |
| 文档 CRUD | 文档/文件夹创建、编辑、删除 | API + store + 页面 |
| 文档树结构 | 父子层级、排序、展示 | `DocumentTree.vue` |
| Markdown 编辑器集成 | 文本内容编辑与保存 | `DocumentEditor.vue` |
| 导入基础能力 | Markdown / TXT 导入 | ImportDialog + API |
| 权限校验 | 私有知识库 owner 校验 | service + API |

**阶段退出标准：**

1. 用户可创建知识库；
2. 用户可维护文档树；
3. 文档新增/编辑/删除可用；
4. 未登录与非 owner 访问受控。

---

## 阶段三：索引与 AI 问答（第 6~8 天）

**目标：** 完成“文档索引 → 检索 → 问答”的业务闭环。

| 任务 | 说明 | 交付物 |
|------|------|--------|
| 文档分块 | chunk 策略与 token 统计 | `chunk_service.py` |
| embedding 封装 | 对接 SiliconFlow embedding | `embedding_service.py` |
| SurrealDB 向量存储 | 写入、删除、检索 | `surrealdb_service.py` |
| RAG 检索 | search / ask / index | `rag_service.py` + API |
| 对话管理 | conversation / history / send | `kb_chat_service.py` + API |
| 前端聊天页 | 对话列表、消息流、引用展示 | `AIChatPage.vue` |
| 知识库页问答侧栏 | 当前知识库上下文问答 | 知识库页集成 |

**阶段退出标准：**

1. 可对已索引知识库发起问答；
2. 回答能显示引用；
3. 支持新建对话与历史查看；
4. 索引失败时有明确状态与错误提示。

---

## 阶段四：增强能力与收尾（第 9~10 天）

**目标：** 收尾、补测、控制风险，P1 能力按时间窗口择机落地。

| 任务 | 说明 | 优先级 |
|------|------|--------|
| AI 助手能力 | 内容改进、质量检查 | P1 |
| 模型管理基础能力 | 模型列表、默认模型、开关 | P1 |
| PDF / DOCX 导入增强 | 依赖解析与测试 | P1 |
| 自动化测试补齐 | 前后端关键路径测试 | P0 |
| 文档回填 | 与实际实现同步 | P0 |
| 性能与异常路径检查 | 超时、空库、权限失败 | P0 |

**阶段退出标准：**

1. P0 闭环稳定；
2. 测试与验收文档可执行；
3. P1 若未完成，必须明确留档，不得隐性拖欠。

---

## 4. P0 / P1 切分原则

### P0

1. 知识库 CRUD
2. 文档 CRUD / 树形结构
3. Markdown/TXT 导入
4. 单知识库索引
5. AI 问答 + 引用
6. 对话管理
7. 菜单与路由
8. 基础权限控制

### P1

1. AI助手
2. 模型管理 UI
3. PDF / DOCX / HTML 导入增强
4. hybrid search / rerank / thinking mode
5. 用量统计面板

---

## 5. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| ReqDocs 源实现不可直接核对 | 迁移描述可能偏差 | 第 1 天必须补核对记录 |
| SurrealDB 环境问题 | 阻塞索引与问答 | 第 1 阶段优先验证环境连通性 |
| 文档导入格式过多 | 延迟主线交付 | Markdown/TXT 先落地，PDF/DOCX 下沉 P1 |
| AI 助手范围失控 | 拖慢 P0 | 明确归入 P1 |
| 前端菜单改动遗漏 currentRoute/pageTitle | 页面高亮和标题异常 | 修改菜单时同步改 3 处 |

## 9. 执行建议

1. 先打通最小链路，不要一开始就同时做 AI助手 / 模型管理 / 高级导入；
2. 先改文档，再改代码，开发中持续回填文档；
3. 所有与 ReqDocs “直接复用”有关的事项，在正式编码前都必须补源码核对。
