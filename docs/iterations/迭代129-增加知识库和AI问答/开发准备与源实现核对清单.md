### 1.1 必核对项

1. ReqDocs 中是否真实存在以下能力：
   - 知识库 CRUD
   - 文档树管理
   - 文档导入
   - 文档分块
   - embedding 调用
   - 向量检索
   - AI 问答对话
   - AI 助手（若计划本期做）

2. ReqDocs 中对应模块的真实命名是否与本文档一致：
   - knowledge base
   - kb chat
   - rag
   - model manager

3. ReqDocs 中以下内容需要记录为“源实现事实”：
   - 真实数据表名 / 集合名
   - 真实 API 路由
   - 真实模型 provider 接入方式
   - 真实导入格式与解析链路

### 1.3 已确认的源码差异（不需要再反复确认）

以下差异已经在源码中确认，可直接作为迁移前提：

1. ReqDocs 以 `projects + documents` 为领域核心；
2. ReqDocs 的 RAG API 以 `project_id` 为主要查询维度；
3. ReqDocs 的 KB Chat 使用整数 ID，并基于 `knowledge_base_id(int)` 管理会话；
4. ReqDocs 的模型配置是 `model_configs + PRESET_MODELS` 组合；
5. ReqDocs 的前端知识库页已经集成文档树、批量操作、导入和 AI问答侧栏；
6. ReqDocs 的 AI 助手页功能比本期 P0 范围更大，应继续保留为 P1。
