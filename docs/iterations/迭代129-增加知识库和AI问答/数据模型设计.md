# 迭代129 - 增加知识库和 AI 问答 - 数据模型设计

> **文档状态**: 已优化，作为开发基线
> **最后更新**: 2026-04-23

---

## 1. 设计目标

为知识库、文档、索引、问答对话提供可落地的数据结构，并与 backtrader_web 现有模型规范保持一致。

约束：

1. 主键统一采用 `String(36)` UUID；
2. 用户表外键统一指向 `users.id`；
3. 结构化数据进入主业务数据库；
4. embedding 向量数据进入 SurrealDB；
5. 模型设计优先支持 P0 闭环，再为 P1 预留字段。

---

## 2. 存储划分

| 存储 | 用途 |
|------|------|
| 主业务数据库（SQLite / PostgreSQL / MySQL） | 知识库、文档、对话、消息、模型配置等结构化数据 |
| SurrealDB | 文档 chunk 与向量 embedding |

---

## 3. ORM 命名建议

建议与现有代码风格保持一致，采用 **复数表名**：

| ORM 类 | 建议表名 |
|--------|----------|
| `KnowledgeBase` | `knowledge_bases` |
| `KBDocument` | `kb_documents` |

## 4. 主业务数据库表设计

## 4.1 knowledge_bases

### 业务说明

用于保存知识库主信息。

### 关键字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(36) | UUID 主键 |
| owner_id | VARCHAR(36) | 所有者，外键 `users.id` |
| name | VARCHAR(255) | 知识库名称 |
| description | TEXT | 描述 |
| document_count | INTEGER | 冗余统计字段 |
| is_public | BOOLEAN | 是否公开 |
| settings | JSON | 扩展配置，如默认模型、chunk 策略 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### SQL 示例

```sql
CREATE TABLE knowledge_bases (
    id VARCHAR(36) PRIMARY KEY,
    owner_id VARCHAR(36) NOT NULL,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    document_count INTEGER DEFAULT 0,
    is_public BOOLEAN DEFAULT FALSE,
    settings JSON,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (owner_id) REFERENCES users(id)
);

CREATE INDEX idx_kb_owner ON knowledge_bases(owner_id);
```

## 4.2 kb_documents

### 业务说明

用于保存知识库中的文档和文件夹。

### 关键字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(36) | UUID 主键 |
| knowledge_base_id | VARCHAR(36) | 所属知识库 |
| title | VARCHAR(500) | 标题 |
| content | TEXT | 文档正文 |
| content_type | VARCHAR(50) | `markdown / text / html` |
| file_path | VARCHAR(1000) | 原始文件路径（如导入文件） |
| is_folder | BOOLEAN | 是否为文件夹 |
| parent_id | VARCHAR(36) | 父节点 ID |
| sort_order | INTEGER | 排序值 |
| status | VARCHAR(20) | `draft / published / archived` |
| index_status | VARCHAR(20) | `not_indexed / indexing / indexed / failed` |
| indexed_at | DATETIME | 最近索引时间 |
| metadata | JSON | 扩展元数据 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### SQL 示例

```sql
CREATE TABLE kb_documents (
    id VARCHAR(36) PRIMARY KEY,
    knowledge_base_id VARCHAR(36) NOT NULL,
    title VARCHAR(500) NOT NULL,
    content TEXT,
    content_type VARCHAR(50) DEFAULT 'markdown',
    file_path VARCHAR(1000),
    is_folder BOOLEAN DEFAULT FALSE,
    parent_id VARCHAR(36),
    sort_order INTEGER DEFAULT 0,
    status VARCHAR(20) DEFAULT 'draft',
    index_status VARCHAR(20) DEFAULT 'not_indexed',
    indexed_at DATETIME,
    metadata JSON,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (knowledge_base_id) REFERENCES knowledge_bases(id) ON DELETE CASCADE,
    FOREIGN KEY (parent_id) REFERENCES kb_documents(id) ON DELETE SET NULL
);

CREATE INDEX idx_kb_doc_kb ON kb_documents(knowledge_base_id);
CREATE INDEX idx_kb_doc_parent ON kb_documents(parent_id);
```

## 4.3 document_chunks

### 业务说明

存储 chunk 元数据；真正向量存储在 SurrealDB 中。

### 关键字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(36) | UUID 主键 |
| document_id | VARCHAR(36) | 对应文档 ID |
| knowledge_base_id | VARCHAR(36) | 冗余知识库 ID |
| chunk_index | INTEGER | 文档内顺序 |
| content | TEXT | chunk 文本 |
| token_count | INTEGER | token 数 |
| source_type | VARCHAR(50) | 来源类型（document/import） |
| created_at | DATETIME | 创建时间 |

### SQL 示例

```sql
CREATE TABLE document_chunks (
    id VARCHAR(36) PRIMARY KEY,
    document_id VARCHAR(36) NOT NULL,
    knowledge_base_id VARCHAR(36) NOT NULL,
    chunk_index INTEGER NOT NULL,
    content TEXT NOT NULL,
    token_count INTEGER,
    source_type VARCHAR(50) DEFAULT 'document',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (document_id) REFERENCES kb_documents(id) ON DELETE CASCADE,
    FOREIGN KEY (knowledge_base_id) REFERENCES knowledge_bases(id) ON DELETE CASCADE
);

CREATE INDEX idx_chunk_doc ON document_chunks(document_id);
CREATE INDEX idx_chunk_kb ON document_chunks(knowledge_base_id);
```

    knowledge_base_id VARCHAR(36) NOT NULL,

## 5. SurrealDB 设计

### 5.1 记录结构建议

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | chunk 唯一标识，建议与 `document_chunks.id` 对齐 |
| document_id | string | 对应文档 ID |
| knowledge_base_id | string | 对应知识库 ID |
| chunk_index | int | 文档内顺序 |
| content | string | chunk 文本 |
| embedding | array<float> | 向量值 |
| created_at | datetime | 创建时间 |

### 5.2 查询目标

支持：

1. 按知识库过滤；
2. 向量相似度排序；
3. 后续可扩展 hybrid search / rerank。

示例：

```surql
SELECT *, vector::similarity::cosine(embedding, $query_embedding) AS similarity
FROM document_chunk
WHERE knowledge_base_id = $kb_id
ORDER BY similarity DESC
LIMIT $top_k;
```

## 7. 设计备注

1. 本版将旧草稿中的 `number` 风格 ID 与 `user(id)` 外键统一纠正为 UUID 字符串与 `users.id`；
2. `index_status` 是本版新增的关键字段，便于前端真实展示索引过程；
3. 如果 P1 模型管理本期暂不落地，也建议保留 `model_id` 字段，避免问答与会话结构返工。
