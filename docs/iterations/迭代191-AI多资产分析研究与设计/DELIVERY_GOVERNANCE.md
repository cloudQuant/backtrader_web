## 1. 目的与治理原则

本文把迭代计划中的资源、依赖、责任和风险转为可执行门禁。它约束“何时可以进入下一阶段”，
不改变产品范围，也不替代各资产插件的 Requirements、Design、Plan 和 Acceptance 文档。

治理遵循以下原则：

1. **门禁优先于日期**：周次是排期基线，不是交付承诺。关键证据未通过时不得用压缩测试、
   跳过迁移演练或扩大并行开发来追赶日期。
2. **公共契约先行**：资产插件只能扩展公共协议，不能私自复制或改写身份、任务、质量、
   决策和报告契约。
3. **一个事实一个权威来源**：Schema、迁移、API、验收和运行指标分别由下文矩阵规定；
   发生冲突时先停止相关发布，再按变更流程消除冲突。
4. **证据可复现**：所有门禁结论必须包含提交号、配置、数据库方言、测试数据版本、命令及
   原始结果；会议结论不能替代验收证据。
5. **范围边界不漂移**：本迭代交付研究与分析能力，不授权自动下单、组合执行或绕过人工确认。
6. **兼容性是硬门禁**：现有股票分析页面、接口和已保存结果的回归失败时，P0c 不得结束。

## 2. 资源与排期基线

- 重排资产顺序或减少同期资产数；
- 延后某阶段的目标日期；
- 缩小可选能力，但不得删除安全、授权、隔离、迁移、兼容或回滚门禁。

不得以无审批加班、共享角色“默认可用”或未验证的自动化产能填补资源缺口。
P0a 进入前必须为 TA、BE、FE、QA、SRE 和 SC 登记具名 primary/backup、可用窗口和
交接位置；独立 QA 的 backup 不能是被验收实现的唯一作者。关键角色连续不可用超过
两个工作日即触发 R-09 和重新排期，不能由未登记人员静默代签。

## 3. P0 分段门禁

### 3.1 统一判定规则

每个门禁结论只能是：

- `GO`：所有硬条件通过，证据完整；
- `CONDITIONAL GO`：只有非安全、非合规、非用户隔离、非迁移完整性的低风险项可限期豁免；
- `NO-GO`：任一硬条件失败、证据缺失或事实来源冲突。

`CONDITIONAL GO` 必须由项目负责人、技术负责人和 QA 共同签署，写明责任人、截止时间和自动
降级条件。安全、数据授权、用户隔离、执行边界、数据库可恢复性不得豁免。

证据统一归档到本迭代的证据目录或 CI 永久链接，并至少记录：

```text
gate_id, decision, commit_sha, environment, db_dialect,
fixture_or_dataset_version, command_or_scenario, result_link,
known_deviation, owner, approvers, decided_at
```

## 5. RACI

R = 执行，A = 最终负责且每项只能一个，C = 必须会签，I = 知会。

- `PO`：项目/产品负责人
- `TA`：技术负责人

- `DR`：领域研究负责人

- `SRE`：DevOps/SRE

## 6. 风险登记册

概率/影响采用 `低/中/高`，状态采用 `开放/监控/缓解中/关闭`。风险所有者每周更新触发信号、
剩余风险和下一动作；触发后必须在一个工作日内执行预案或升级。
执行期风险记录还必须保存 `last_reviewed_at/next_review_at`；下次复审不得晚于下一次
周度风险审查或相关阶段 Gate，以较早者为准。

## 7. 变更控制

### 7.1 变更等级

| 等级 | 示例 | 审批 | 最低要求 |
| --- | --- | --- | --- |
| C0 文档澄清 | 拼写、链接、不改变语义的说明 | 文档所有者 | 同 PR 审查 |
| C1 向后兼容 | 新增可选字段、提高内部观测、非破坏性阈值调整 | TA + QA；涉及来源时加 SC | 影响分析、回归、版本记录；命中 ADR 触发器时附 ADR |
| C2 破坏性/范围变化 | 删除或改义字段、枚举/状态变化、迁移、API 路径、模型动作、留存缩短 | PO + TA + QA；按领域加 SC/MR | ADR、迁移、兼容期、回滚、全量复验和文档同步 |
| C3 紧急安全/合规 | 泄露、越权、授权撤销、严重漏洞 | SC 或事故指挥可先停用；24 小时内补签 | 立即禁用/回滚、事件记录、后评审 |

### 7.2 流程

任何 C1–C3 变更必须有唯一变更单，至少包含：

1. 问题、目标和不做变更的影响；
2. 受影响的契约、表、API、插件、前端、数据、指标、测试和文档；
3. 向前/向后兼容策略、数据迁移、回滚点和停止条件；
4. 安全、授权、模型、成本和排期影响；
5. 责任人、批准人、目标版本和证据链接。

以下变更必须在实现前于 `docs/adr/` 新建版本控制的 ADR，并由变更单引用：

- 公共 Schema、API 路径/语义、枚举或状态机；
- canonical identity、幂等/hash 输入域、cutoff/PIT、动作真值表；
- outcome/head/评分/晋级口径、数据库方言策略或迁移拓扑；
- 保留/删除、用户隔离、安全、合规、数据许可或执行边界；
- 替换公共编排、状态所有权、观测主链等跨两个以上插件的架构选择。

ADR 至少包含 context、decision、considered alternatives、consequences、受影响契约、
兼容/迁移/回滚方案、验证证据、owner/approvers、状态、生效版本和 supersedes/superseded-by。
已批准 ADR 不原地改写结论；后续变化通过新 ADR supersede，并保留旧文件及提交哈希。
C3 可先停用/回滚，但必须在 24 小时内补建事件 ADR 或安全事件决议并关联原始时间线。

执行顺序为：

```text
提出 → 分类 → 影响分析/ADR → 审批 → 实现/迁移 → 独立验证
     → 文档与版本同步 → Gate 复判 → 发布或回滚
```

以下行为视为未批准的 C2：在资产插件中复制公共状态机、用新枚举替换旧值但无映射、改变
canonical ID、修改历史 hash 输入、绕过来源授权、把研究结论改成交易动作、删除旧 API 而无
兼容期。

### 7.3 冻结和例外

- P0a 冻结公共 Schema、插件协议、reason code、动作真值表和身份规则；
- P0b 冻结公共 API、任务状态机、核心指标名和前端状态映射；
- P0c 冻结股票兼容契约和后续插件参考实现。

冻结后 C1/C2 变更必须重新执行受影响 Gate。紧急 C3 可以先关闭功能或来源，但不能在事故中
静默改写历史结果；恢复前仍须完成复验。

## 8. 运行节奏与升级

| 节奏 | 参与者 | 固定输出 |
| --- | --- | --- |
| 每日关键路径检查 | TA、BE、FE、QA | 阻塞、依赖、当天证据 |
| 每周风险与资源审查 | PO、各责任人、SC/MR 按需 | 风险登记册、资源偏差、变更单 |
| 阶段门禁评审 | 对应 RACI 批准人 | GO/CONDITIONAL GO/NO-GO 记录 |
| 受控运行复盘 | SRE、QA、BE、DR、SC | 指标、失败、预算、数据授权和模型状态 |

出现以下任一情况应立即升级给项目负责人和对应一票否决角色：

- 数据越权、跨用户泄露、授权撤销或出现执行能力；
- 迁移无法回滚、数据账实不符或身份串标的；
- T1 硬门禁失败但仍计划放量；
- 模型在 T2 未通过时被标记为建议或可执行；
- 预算耗尽、告警失效或关键链路不可观测。

### 8.1 P6 影子运行所有权与关闭条件

- PO 对 P6 是否继续、暂停或结束最终负责；SRE 负责调度与告警，DR 负责数据/标签质量，
  QA 负责证据完整性，MR 与 SC 分别对模型晋级和合规保留否决权；
- 进入 P6 前必须有 T1 `GO`、审批 schedule manifest、值守表、dashboard、告警、
  补跑 runbook 和明确的下一复审日期；
- 每周检查运行健康、来源/许可、覆盖率和评分积压；每月形成一次
  `CONTINUE/SUSPEND/PROMOTION_REVIEW/RETIRE` 决议；
- 一般资产至少 60 个交易日、数字货币至少 90 个自然日只是最短观察期；T2 还必须满足
  成熟样本、校准、净效用、基线和审批的全部门槛；
- 未满足 T2 但运行健康时只能 `CONTINUE` 并给出证据缺口与下次复审；许可撤销、关键
  不变量失败或持续低于已批准停止阈值时必须 `SUSPEND`；
- 达到 T2 后进入独立 promotion review，不自动打开方向建议；确认无法在批准的数据、
  范围或成本内形成有效证据时，以不可变决议 `RETIRE`，保留历史评分和审计。

## 9. 阶段签署清单

每次 Gate 评审前，QA 必须确认：

- [ ] 证据绑定当前提交、配置、数据库方言和 fixture/数据集版本；
- [ ] 所有依赖矩阵中的上游版本一致，没有未裁决冲突；
- [ ] 风险登记册已更新，触发项已执行预案；
- [ ] C1–C3 变更均有审批、迁移/兼容和回滚证据；
- [ ] 非功能测量符合 [NON_FUNCTIONAL_REQUIREMENTS.md](./NON_FUNCTIONAL_REQUIREMENTS.md)；
- [ ] 用户隔离、数据授权、执行边界和旧股票兼容没有豁免；
- [ ] `GO`、`CONDITIONAL GO` 或 `NO-GO` 已由 RACI 中的批准人签署。
