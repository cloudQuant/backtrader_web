## 2. 废弃标记验证

### 2.1 `app/api/backtest.py` — ✅ 已标记

- 整个路由器在 `router.py` 中注册时标记为 `deprecated=True`
- 每个端点函数内部调用 `mark_deprecated(response, _DEPRECATED_SUCCESSOR, "backtest")`
- 设置 `Deprecation: true` 响应头
- 设置 `Link: </api/v1/backtests>; rel="successor-version"` 响应头
- 每个函数的 docstring 包含 `.. deprecated:: 1.0.0` 标记

### 2.2 `app/api/live_trading.py` — ✅ 已标记

- 路由器创建时标记为 `APIRouter(deprecated=True)`
- 在 `router.py` 中注册时也标记为 `deprecated=True`
- 每个端点函数内部调用 `mark_deprecated(response, _DEPRECATED_SUCCESSOR, "live-trading-crypto")`
- 设置 `Deprecation: true` 响应头
- 设置 `Link: </api/v1/live-trading>; rel="successor-version"` 响应头

### 2.3 `app/api/backtest_enhanced.py` (optimization endpoints) — ✅ 已标记

- `grid_search_optimization` 和 `bayesian_optimization` 路由定义中设置 `deprecated=True`
- 内部调用 `_mark_legacy_optimization_proxy(response, method)` 设置:
  - `Deprecation: true` 响应头
  - `Link: </api/v1/optimization/submit/backtest>; rel="successor-version"` 响应头
  - `X-Deprecated-Endpoint` 响应头
  - 日志警告

### 2.4 `app/middleware/deprecation.py` — ✅ 全局中间件

- `DeprecationHeadersMiddleware` 作为 ASGI 中间件在 `app/main.py` 中注册
- 为所有匹配废弃前缀的请求自动添加 RFC 8594 标准头:
  - `Deprecation: true`
  - `Sunset: 2026-09-30T00:00:00Z`

  - `X-Deprecated-Endpoint: <successor>`

  - `/api/v1/backtest/` → `/api/v1/backtests/`

## 6. 废弃机制总结

当前系统采用**双重废弃标记**策略：

1. **路由级别**: FastAPI `deprecated=True` 参数（影响 OpenAPI 文档）
2. **函数级别**: `mark_deprecated()` 在每个请求中设置响应头
3. **中间件级别**: `DeprecationHeadersMiddleware` 作为兜底，确保即使函数遗漏也能添加头
4. **文档级别**: Docstring 中的 `.. deprecated::` 标记

这种多层策略确保了：
- OpenAPI/Swagger UI 中显示废弃标记
- 每个响应都包含 `Deprecation: true` 头
- 客户端可以通过 `Sunset` 头了解移除时间
- `Link` 头指向替代端点
