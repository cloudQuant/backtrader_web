## 验收驱动的四个真实迁移缺陷（全部先写失败测试再修复）

在真实 MySQL 9.4 上第一次 `--apply` 起，迁移链连续暴露四个方言缺陷；每个都按“离线失败测试 → 修复 → 全量回归”处理：

1. **`md_visibility_sequence_allocator` 建表失败（MySQL 3818）**：整数主键未标注 `autoincrement=False`，MySQL 方言渲染 AUTO_INCREMENT，而 singleton CHECK 引用该列被 MySQL 拒绝。修复：模型与迁移（`20260908_market_data_visibility_anchor`）同时固定 `autoincrement=False`；新增 `test_visibility_allocator_singleton_has_no_mysql_autoincrement`（MySQL 方言 DDL 编译断言）。
2. **`20260909_market_data_constraint_name_portability` 误报 drift**：`_normalized_expression` 只处理 PostgreSQL `::text`，不认 MySQL 反射的反引号与子句括号形态。修复：两侧统一去反引号与分组括号（该迁移的 3 个 CHECK 均为线性布尔，token 序列保留语义）；新增 `test_constraint_portability_normalizes_mysql_reflected_check_text`（含 63 长度的真漂移反例）。
3. **`20260908_ai_research_holdout_executions` 误报 `HOLDOUT_EXECUTION_ACCESS_SCHEMA_CONFLICT`**：MySQL 9 把每个字符串字面量反射为 `_utf8mb4'...'` 字符集引入符形态并给子句加括号。修复：`_sql_matches` 剥离 `_[A-Za-z0-9]+'` 引入符与全部分组括号；新增 `test_sql_matches_accepts_mysql_clause_parentheses`（含不同操作数反例）。
4. **`20260908_ai_research_approval_authority` 双缺陷**：(a) `_normalize_sql` 同样不认字符集引入符；(b) 完整性探针原生 SQL 使用 MySQL 保留字 `grant` 作别名导致 1064 语法错误。修复：tokenize 前剥离引入符；全部原生探针别名 `grant` 改为 `issued_grant`（同步更新既有渲染断言）；新增 `test_normalize_sql_accepts_mysql_charset_introducers`（含不同字面量反例）。

修复后完整迁移链在一次性空库上从 base 升级到唯一 head `20260911_market_data_b2_completeness_evidence` 成功；`tests/market_data_platform tests/test_config.py` 全量回归 `1175 passed`，196 迁移相关回归 `153 passed, 3 skipped`（MySQL contract 为 opt-in skip），目标 Ruff 全部通过，`alembic heads` 保持单 head。

证据解读（每项独立断言，全部通过才输出 `MYSQL_ACCEPTANCE_CORE_PASSED`）：

- **迁移与结构**：16 张必需表存在；`asset_instruments`/`md_instrument_identity_revisions`/`md_instrument_lookup_keys` 的 9 个身份列实测 `utf8mb4_bin`；`md_observation_revisions`/`md_publications`/`md_calendar_events`/`md_fetch_leases` 的 7 个 PIT 列实测 `DATETIME(6)`。
- **UTC/微秒**：aware UTC 微秒时刻经 `CAST(... AS DATETIME(6))` 往返无漂移（session `time_zone=SYSTEM` 被如实记录；DATETIME(6) 本身无时区，UTC 语义由应用层规范化保证，此探针验证存储精度）。
- **RB0/rb0 case-distinct**：两个仅大小写不同的期货身份各自解析为不同 canonical_id；错误大小写 `Rb0` 稳定失败——MySQL `utf8mb4_bin` 下无 `*_ci` 折叠。
- **identity PIT 微秒边界**：`published_at=…22.772868+00:00` 的投影在其前 1µs cutoff 不可见、恰在该时刻可见（DATETIME(6) 微秒精度真实生效）。
- **受治理 downgrade**：对已有 3 行身份数据的库执行 `alembic downgrade -1` 被拒绝（RuntimeError），head 未移动、数据行保留。
