# 市场数据与可信度

市场数据页将“查看本地数据”和“主动拉取在线行情”分开，避免页面加载被上游数据源阻塞，也避免 AkShare 故障覆盖已有可用数据。

## 本地优先、显式刷新

- 默认从 `AKSHARE_DATA_DATABASE_URL` 指向的本地 MySQL 行情仓库读取标的快照、历史、覆盖与质量信息。
- 用户选择资产类别或标的时不主动请求 AkShare。
- 只有点击**查询**才会发出在线刷新请求；成功的在线历史可写入补齐缓存。
- 若在线请求失败、没有覆盖所选区间或返回无效数据，页面保留 MySQL 数据，并显示不含原始数据库凭据的可读提示。

## 页面行为

| 行为 | 说明 |
| --- | --- |
| 标的记忆 | 每个资产类别单独记住上次选择的具体标的，不会跨类别串用。 |
| 历史排序 | 最新日期排在前面，旧日期随后。 |
| 覆盖与质量 | 显示数据范围、缺口或质量警告；回测前应执行预检。 |
| 快照与指标 | 基于当前有效历史计算，在线数据不会在无效时替换本地结果。 |

## 使用建议

1. 先检查品种、周期、日期范围和本地覆盖是否满足研究需要。
2. 需要最新行情时再点击查询，并记录数据来源与时间范围。
3. 若 MySQL 不可用，检查数据仓连接和授权；接口只给出可操作提示，不暴露服务器、用户或密码。
4. 将通过预检的数据范围和策略配置一起保存到研究工作区，保证回测可复现。

主应用数据库的 `DATABASE_URL` 与行情仓库 `AKSHARE_DATA_DATABASE_URL` 是两条独立连接。配置请见[配置参考](../reference/configuration.md)。
